# Changelog

**BareD does not maintain a hand-written changelog. The GitHub Releases page is the
changelog:**

### 👉 https://github.com/etowett/bared/releases

Every release there carries generated notes grouped into Features, Breaking Changes,
Bug Fixes, Documentation and Maintenance, plus install instructions and checksums.

## Why there's no hand-written file

Release notes are generated by [GoReleaser](https://goreleaser.com) from merged pull
request titles and conventional-commit prefixes (`.goreleaser.yml`). A second,
manually-maintained copy would only drift out of date — and a stale changelog is
worse than none.

## How versions are decided

Releases are automatic. When a PR merges to `main`, its release label determines the
version bump:

| Label | Bump | For |
|-------|------|-----|
| `release:major` | x.0.0 | Breaking changes |
| `release:minor` | 0.x.0 | New features |
| `release:patch` | 0.0.x | Bug fixes, docs, small improvements |
| `release:skip` | none | Internal changes with no user impact |

If no label is set, a patch release is created. Maintainers apply the label — outside
contributors don't need to. See [CONTRIBUTING.md](CONTRIBUTING.md#release-process) for
the full process.

## Reading the history another way

```bash
# Releases, newest first
gh release list

# Notes for one release
gh release view v0.4.0

# What changed between two versions
git log --oneline v0.3.8..v0.4.0
```

## Compatibility

BareD is pre-1.0. Configuration and interfaces may change between minor versions —
see [Project status](README.md#project-status) before upgrading, and read the release
notes rather than assuming semver guarantees that don't apply yet.
